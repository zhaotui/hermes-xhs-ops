小红书自动化运营系统 — 产品方案

版本: v1.0 | 日期: 2026-06-01

一、项目概述

1.1 定位

基于 Hermes Agent 插件体系的全自动小红书运营系统。通过浏览器自动化 + AI 调度，替代人工完成发帖、评论监控、信息收集、多账号管理等重复性运营工作。

1.2 核心价值

痛点 解决方案
多账号切换繁琐 一键切换登录态（cookie + localStorage 快照）
手动发帖效率低 模板化发布，支持从 EHR 系统自动读取职位
评论信息流失 自动扫描 + 分类 + 收集到结构化数据
运营无数据沉淀 每次操作自动生成报告，可回溯

三、功能模块

3.1 多账号管理

支持多个小红书账号的登录态保存与快速切换。

账号配置 (accounts.json):

default    → (通用)
main       → 王童
brand      → 李汶霖
小红薯68761c00 → 马雨琦

核心操作: - add — 新增账号（关联 EHR 创建人） - save_state — 保存当前登录态（cookie + localStorage） - switch — 恢复登录态 + 切换浏览器 session - detect — 检测当前浏览器登录的账号昵称

已知限制: Cookie 通过 CDP Network.setCookies 设置，不持久化。标签页关闭后需重新切换。

3.2 自动发帖

支持长文笔记发布，完整覆盖小红书创作流程。

发布源: - 手动指定标题正文（AI 可帮忙写） - EHR 系统自动读取待发布职位

发布流程:

打开发布页 → 切换长文 → 新建创作 → 填标题正文
→ 一键排版 → 选择模板 → 下一步 → 填描述
→ 设置可见范围 → 发布

关键参数: | 参数 | 说明 | |------|------| | title | 标题，≤30字 | | body | 正文（支持排版模板） | | images | 图片路径列表 | | visibility | private/public/friends | | location | 发布地点 | | save_draft | 仅暂存不发布 |

EHR 职位发布模板:

【招聘】{职位名}

📍 {城市}  |  💰 {薪资}  |  🏢 {部门}

📋 {职位描述}

---
#招聘 #求职 #{城市}

3.3 评论监控

从笔记管理页进入详情页，自动提取全部评论。

流程:

笔记管理页 → 点击封面 → 切换到详情页 → 提取评论 JSON

输出: {comments: [{authorName, text, timeText, isAuthor}], count, noteUrl}

注意: 自动过滤作者自己的回复（isAuthor: true），区分真实用户互动。

3.4 信息收集

对评论进行二分类，有价值的自动写入结构化数据。

分类规则:

正向信号命中 → useful     → 写入 records.jsonl
无命中       → ignore     → 丢弃

正向信号示例: 感兴趣、想了解、怎么报名、求带、在哪里

存储格式 (JSONL):

{
  "type": "xhs_collected_info",
  "platform": "xiaohongshu",
  "sourceType": "comment",
  "authorName": "用户昵称",
  "sourceText": "评论内容",
  "classification": "useful",
  "capturedAt": "2026-06-01T10:00:00+08:00"
}

去重: 基于 (goal, authorName, sourceText) 三元组。

3.5 评论回复

在笔记详情页对指定评论进行回复。

安全规则: 回复前检查是否存在作者自己的回复，避免重复回复。

3.6 安全删帖

仅删除"仅自己可见"的帖子（测试帖清理）。

安全机制: 1. 先扫描识别所有"仅自己可见"帖 2. 列出待删列表，等待确认 3. 逐个删除 + 验证

绝不盲删。

3.7 自动运营 (Auto Pilot)

通过 Hermes cron 实现定时自动化。

预设任务:

每 N 分钟  → 扫描评论 + 分类 + 输出报告
每天 10:00 → 发布 EHR 待发职位
每周日凌晨 → 清理测试帖

每次执行自动: - 生成运营报告 → ~/.hermes/data/xhs-ops/reports/ - 报告格式规范: 标题 + 时间戳 + 分节数据

四、数据流

4.1 EHR → 小红书

EHR 创建职位
    │
    ▼
前端调 saveXhsPublishJob() → 写入 IndexedDB (ehr_xhs_publish/jobs)
    │
    ▼
Hermes (cron/手动) 触发 ehr-xhs-publish
    │
    ├── webbridge evaluate → 读 IndexedDB getAll
    ├── 按 creator 匹配 xhs 账号 (linked_creator)
    ├── 格式化正文（模板渲染）
    ├── xhs_publish_post → 浏览器发帖
    └── 发布成功 → webbridge delete(id)

4.2 评论数据流

xhs_read_comments
    │
    ├── 提取评论 JSON
    ├── xhs_collect_info → 分类 (useful / ignore)
    ├── useful → 追加 records.jsonl
    └── xhs_reply_comment (可选)

4.3 报告输出

每次操作结束
    │
    └── 生成报告 → reports/{标题}_{时间}.md
         ├── 概况（总数、有效数）
         ├── 明细（逐条列表）
         └── 分析（趋势、建议）

五、部署方案

5.1 环境要求

组件 说明
Windows 10/11 浏览器运行环境
WSL2 Hermes Agent 运行环境
Chrome 带 Kimi WebBridge 扩展
Kimi WebBridge 浏览器自动化桥接 (端口 10086)
Hermes Agent AI 调度引擎
Python 3.11+ 脚本运行

5.2 安装步骤

Windows 端:

# 1. 安装 Kimi WebBridge 扩展 + 桥接服务
powershell -ExecutionPolicy Bypass -File .\deploy\install-webbridge.ps1

# 2. 确保 Chrome 常开 + 登录小红书

WSL2 端:

# 1. 克隆插件
git clone <repo> ~/.hermes/plugins/xhs

# 2. 一键安装
cd ~/.hermes/plugins/xhs && bash deploy/install.sh

# 3. 首次配置账号
hermes     # 启动对话，然后:
# xhs_account_manager(action="detect")  确认昵称
# xhs_account_manager(action="add", key="main", nickname="XXX", linked_creator="王童")
# xhs_account_manager(action="save_state", key="main")

5.3 生产环境要求

  • Windows 电源设置"永不睡眠"
  • Chrome 保持运行（不关闭）
  • WebBridge daemon 保持运行
  • WSL2 不自动休眠 (vmIdleTimeout=-1)

六、运营指标

指标 数据来源 说明
发布帖数 报告 每次发布自动记录
评论总量 报告 扫描统计
有效线索 records.jsonl useful 分类计数
回复率 报告 已回复 / 应回复
账号活跃度 accounts.json 各账号发帖频率
